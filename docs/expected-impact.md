# 밥픽 기대효과

**한 줄 정의**: "오늘 뭐 먹지?"의 결정 피로를 줄이고, 개인 취향·알러지·미식 콘텐츠를 한곳에 모아주는 **개인화 메뉴 추천 서비스**.

## 1. 사용자 — 핵심 문제 해결
- **결정 피로 감소**: 매일 반복되는 "뭐 먹지" 고민을, 취향·최근 먹은 것·인기를 반영한 추천 카드로 3초 만에 좁혀줌.
- **알러지 안전**: 알러지는 사용자가 끌 수 없는 **하드 제외 조건**이라, 추천에서 원천 차단 → 안심하고 선택.
- **탐색성(발견)**: 이미 좋아요한 건 빼고, 취향이 겹치는 사람이 좋아한 새 메뉴를 노출 → "새로운 메뉴 발견".

## 2. 참여·리텐션 (계속 오게 만드는 힘)
- **기록 습관화**: 식사 기록 → 달력·음식 통계로 시각화되니 "계속 기록할 이유"가 생김.
- **소셜 신호**: 후기·평점·좋아요, 실시간 인기 순위 → "남들은 뭐 먹나" 재미로 재방문.
- **재추첨·랜덤픽**: 전체 새로고침, MY밥픽 랜덤 골라줌 → 가볍게 만지작거리는 인터랙션.

## 3. 데이터 선순환
- 좋아요·후기·기록이 쌓일수록 **협업 필터링 추천 품질이 향상** → 쓸수록 똑똑해지는 구조.
- 축적된 취향/기록 데이터는 향후 개인화·마케팅·수요예측의 기반.

## 4. 외부 미식 콘텐츠 연계
- **유튜브 음식 리뷰** + **미슐랭 가이드 · 블루리본 서베이 칼럼**을 대시보드에 큐레이션.
- 효과: **자체 콘텐츠 제작 비용 0으로 "믿을 만한 미식 정보"를 얹어** 체류시간↑·신뢰도↑. 추천(먹을 것)과 콘텐츠(볼 것)를 한 화면에 → **"미식 허브"** 로서의 포지셔닝.

## 5. 기술·확장성
- 웹/앱/DB **3계층 분리 + 무상태(세션 Redis) + 설정 환경변수화**로 설계 → 코드 변경 최소로 **AWS·컨테이너 확장 가능**(1→2→3단계 로드맵).
- 즉, "지금은 서버 2대지만 트래픽이 늘어도 그대로 확장되는 구조"라는 **성장 대비 설계**가 기대효과.

## 6. 팀/포트폴리오 어필 포인트 (발표용)
- **풀스택 역량**: 추천 로직·데이터 모델·UI·외부 API/스크래핑 연동까지 직접 구현.
- **인프라 역량**: 온프레미스 3계층 배포, HTTPS 전환, 서버 물리 분리, 마이그레이션 이슈 진단·해결(트러블슈팅 문서화).
- **문제해결 스토리**: "각자 DB → 단일 DB 정상화", "--fake를 바로 안 쓴 이유" 등 **엔지니어링 판단**을 보여줄 수 있음.

## 측정 가능한 지표(예시)
재방문율(DAU/WAU), 1인당 기록·좋아요·후기 수, 추천 클릭률, 추천 → 기록 전환율, 평균 체류시간(유튜브·칼럼 섹션 도입 전후 비교), 신규 가입 시 선호/알러지 입력 완료율.
