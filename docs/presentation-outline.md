# 밥픽 인프라 발표 슬라이드 개요

> `docs/deployment-infra-guide.md`(상세 스터디)의 **발표용 압축본**. 슬라이드 1장 = 아래 1블록.
> 각 블록의 **말할 것**은 대본, **슬라이드**는 화면에 띄울 요지다. 8~10분 분량.

---

## S1. 타이틀
- **슬라이드**: 밥픽 — 메뉴 추천 서비스 / 팀 2인 / 온프레미스 배포
- **말할 것**: "저희는 Django 기반 메뉴 추천 웹서비스를 직접 서버에 올려 운영했고, 오늘은 그 인프라 구조와 배포 과정을 소개합니다."

## S2. 한 줄 아키텍처
- **슬라이드**: **웹서버(Nginx) · 앱서버(Gunicorn+Django) · 데이터(MariaDB+Redis)** 3계층, 서버 2대
- **말할 것**: "핵심은 계층 분리입니다. 요청을 받는 웹 계층, 로직을 처리하는 앱 계층, 데이터를 보관하는 데이터 계층을 나눴습니다."

## S3. 구성도 (다이어그램)
- **슬라이드**: 브라우저 →(HTTPS)→ Nginx →(유닉스 소켓)→ Gunicorn → Django →(TCP)→ MariaDB/Redis
  - Server1(192.168.32.74): Nginx + Gunicorn + Django
  - Server2(192.168.32.73): MariaDB + Redis
- **말할 것**: "사용자 요청은 이 순서로 흐릅니다. 오른쪽 데이터는 별도 서버에 둬서 DB를 외부에 노출하지 않습니다."

## S4. 요청 한 번의 여정 (스토리)
- **슬라이드**: ① Nginx가 HTTPS 종료 ② 정적파일은 Nginx가 직접 / 나머지는 Gunicorn ③ Gunicorn→Django ④ Django가 MariaDB·Redis 조회 ⑤ 응답
- **말할 것**: "**Nginx는 문지기, Gunicorn은 통역사, Django는 일꾼**으로 비유할 수 있습니다. Nginx가 암호화를 풀고 정적파일을 처리한 뒤, 동적 요청만 Gunicorn을 거쳐 Django로 갑니다."

## S5. 왜 Nginx + Gunicorn 둘 다?
- **슬라이드**: Nginx=웹서버(HTTPS·정적·동시접속) / Gunicorn=앱서버(파이썬 실행) / runserver는 개발용
- **말할 것**: "역할이 다릅니다. Django 내장 서버는 개발용이라 운영 트래픽을 못 버팁니다. 그래서 앞단·뒷단으로 나눕니다."

## S6. HTTPS 처리 (TLS 종료)
- **슬라이드**: Nginx에서 TLS 종료 → 뒤는 평문 → `X-Forwarded-Proto` 헤더로 원 스킴 전달 → Django `SECURE_PROXY_SSL_HEADER`
- **말할 것**: "암호화 해제는 Nginx가 하고, '원래 https였다'는 정보를 헤더로 넘겨 Django가 보안 연결로 인식하게 합니다. 이걸 빼먹어서 리다이렉트 무한루프를 겪었고, 이 설정으로 해결했습니다."

## S7. 상태를 앱에 두지 않기 (세션=Redis) ★
- **슬라이드**: 세션을 앱 메모리 X → Redis O → 앱 서버 여러 대여도 로그인 유지(수평 확장)
- **말할 것**: "가장 중요한 설계 결정입니다. 세션을 Redis에 둬서, 나중에 앱 서버를 늘려도 어느 서버로 요청이 가든 로그인이 유지됩니다."

## S8. 설정·파일도 밖으로 (.env / storages)
- **슬라이드**: 시크릿·DB주소는 `.env`(깃 제외) / 업로드 파일은 django-storages
- **말할 것**: "비밀번호는 코드에 안 박고 환경변수로, 업로드 파일도 로컬 디스크가 아니라 외부 스토리지 전제로 설계했습니다. 코드는 그대로, 값만 바꿔 배포합니다."

## S9. 배포 과정
- **슬라이드**: `git pull` → (필요시) `migrate` / `collectstatic` → `systemctl restart gunicorn`
- **말할 것**: "코드를 받고, 마이그레이션·정적파일을 반영한 뒤 Gunicorn을 재시작합니다. 데이터는 즉시 반영되지만 코드·템플릿은 재시작이 필요합니다. systemd가 부팅 시 자동 실행·장애 시 재시작까지 관리합니다."

## S10. 왜 이렇게? — 확장 로드맵
- **슬라이드**: 1단계 온프레미스(현재) → 2단계 AWS → 3단계 컨테이너 / 절대원칙 ↔ ALB·EC2·RDS·ElastiCache
- **말할 것**: "지금은 서버 2대지만, 상태·설정·파일을 처음부터 밖으로 빼놨기 때문에 코드를 거의 안 고치고 AWS·컨테이너로 확장할 수 있습니다."

## S11. 트러블슈팅 (인상 포인트)
- **슬라이드**: 포트 충돌 / HTTPS 리다이렉트 루프 / 정적파일 미반영 / 마이그레이션↔DB 드리프트
- **말할 것**: "실제로 이런 문제들을 겪고 로그를 추적해 해결했습니다. (한두 개 골라 30초씩 사례 설명)"

## S12. 마무리 / Q&A
- **슬라이드**: 계층 분리 · 무상태 · 환경변수 = 확장 가능한 설계
- **예상 질문 대비**: 상세본 `deployment-infra-guide.md` §8 참고

## 부록 슬라이드 — 서버 물리 분리 사례 (마이그레이션 이력 불일치) · 2026-07-21

> 위 §11(트러블슈팅)에서 **"삽질 스토리 1개"로 이걸 뽑아 쓴다.** 핵심 메시지는 **"왜 `--fake`를 바로 쓰지 않았는가"**.
> 흐름: 처음 구성과 한계 → 에러 화면 → 진단 과정 → 원인 → 처방과 근거.

### A1. 처음 구성과 그 한계
- **슬라이드**: "웹+DB 한 세트를 각자 PC에 복제" 그림 → 사실상 **두 개의 서비스를 각자 운영**. 코드는 Git으로 합쳐도 **DB 데이터·마이그레이션 이력은 안 합쳐진다.**
- **말할 것**: "각자 환경에서 개발한 게 편해 보였지만, 기준이 되는 단일 DB가 없다는 게 병합 때 터졌습니다."

### A2. 에러 화면 (문제 제시)
- **슬라이드**: DB 복원 후 `migrate` 실행 → `OperationalError: (1060, "Duplicate column name 'cuisine_id'")`
- **말할 것**: "복원은 됐는데 마이그레이션에서 '컬럼이 이미 있다'며 멈췄습니다. DB가 깨진 걸까요?"

### A3. 진단 과정 (이 발표의 핵심 — 단계별로)
- **슬라이드**(가설→검증 5단계):
  1. 데이터 유실? → `COUNT` 199/59, `SHOW TABLES` 23개 → **정상**
  2. Django 적용 이력? → `django_migrations`에 `0002_allergy_...` 등 기록
  3. 코드의 파일과 대조 → 코드엔 `0002_initial` → **이름 계보가 다름**
  4. 코드가 옛 버전? → `git status`/`log` → **최신. pull로 해결 아님**
  5. 스키마는 맞나? → `SHOW COLUMNS` → `cuisine_id`·`review_type` 이미 존재 → **스키마는 최신, Django만 미적용으로 오인**
- **말할 것**: "데이터 → 스키마 → 이력 순으로 좁혔습니다. **증상은 migrate에서 났지만 원인은 코드-DB의 이력 불일치**였습니다."

### A4. 원인
- **슬라이드**: 각자 `makemigrations` + 충돌 때마다 파일 **삭제·재생성** → 파일명 계보가 배포된 DB 기록과 갈라짐. 스키마는 이미 반영 → migrate가 다시 실행하려다 컬럼 중복.
- **말할 것**: "마이그레이션 파일을 지웠다 다시 만든 게 근본 원인이었습니다."

### A5. 처방과 그 근거 (★"왜 --fake를 바로 쓰지 않았는가")
- **슬라이드**: `SHOW COLUMNS`로 **스키마 일치를 컬럼 단위로 먼저 확인** → 그 뒤에야 `migrate accounts --fake`(기록만 남김) → `showmigrations` 전부 `[X]` → 재시작 → 화면 검증.
- **말할 것**: "`--fake`는 'SQL 없이 적용됐다고 기록만' 하는 명령입니다. **스키마가 실제로 맞는지 확인 없이 쓰면**, Django는 됐다고 믿는데 DB엔 컬럼이 없는 **더 찾기 어려운 상태**가 됩니다. 그래서 확인을 먼저 하고, 확인된 뒤에만 `--fake`를 썼습니다."
- **마무리 한 줄**: "그래서 팀 규칙을 세웠습니다 — **마이그레이션은 지우지 않는다, 한 사람이 만든다, `--fake`는 확인 뒤에만.**"

> 예상 질문 대비: `--fake`가 뭐냐 / 왜 DB를 안 고치고 기록만 고쳤냐 / 재발 방지책 → 상세는 `docs/troubleshooting.md` 2026-07-21 항목1, 절차는 `docs/data-migration-procedure.md`.
