시스템 아키텍처 및 확장성

⭐ 집중
🗣 말할 순서
  • ·
    3계층 쓰리 티어 인프라
    "저희 인프라는 웹·앱 서버와 DB를 물리적으로 분리한 3계층 구조입니다."
  • ①
    물리 분리 2대
    Server1 = Nginx·Gunicorn·Django / Server2 = MariaDB·Redis. 실제 두 대로 나눔.
  • ②
    Nginx = 문지기
    443 포트에서 암호화를 풀고 정적 파일을 직접 처리. 맨 앞단 방어선.
  • ③
    Gunicorn (WSGI 더블유에스지아이)
    동적 요청만 Gunicorn 거쳐 Django로. 데몬 등록이라 서버 꺼져도 자동 재시작.
  • ★
    확장성 = 무상태 스테이트리스
    세션을 앱 메모리가 아니라 Redis에 분리 저장 → 앱 서버를 수평 확장해도 어느 서버로 가든 로그인 유지.
  • ④
    .env 닷 이엔브이 분리
    시크릿 키·DB 정보를 코드 밖 .env로 → 환경만 바꾸면 그대로 이관.
  • ⑤
    AWS 이관 로드맵
    이 표준 설계 덕에 코드 안 고치고 EC2·RDS로 무중단 이관 가능.
  • ➡️
    전환 → 8번 배포 일지
    "이 인프라를 실제로 어떤 단계를 거쳐 구축했는지, 배포 일지로 보여드리겠습니다."
📖 용어 (읽는법 · 뜻)
  • 3계층 / 3-Tier쓰리 티어웹·앱·DB를 계층으로 나눈 구조.
  • WSGI더블유에스지아이웹 서버와 파이썬 앱을 연결하는 표준 규격. Gunicorn이 그 역할.
  • 데몬Daemon · 데몬백그라운드에서 계속 도는 프로그램.
  • systemd시스템디데몬을 관리하고 자동 재시작해 주는 리눅스 도구.
  • 무상태Stateless · 스테이트리스세션 같은 상태를 앱 서버에 저장하지 않는 구조. 서버 증설이 자유로움.
  • 수평 확장Horizontal Scaling서버 대수를 늘려 부하를 나누는 것.
  • .env닷 이엔브이비밀번호·주소 같은 설정값을 담는 환경변수 파일.
  • AWS · EC2 · RDS에이더블유에스 · 이씨투 · 알디에스아마존 클라우드. EC2=서버, RDS=관리형 데이터베이스.
8

실전 배포 일지 — 4단계

⭐ 집중
🗣 말할 순서
  • 1
    runserver 런서버 (개발용)
    개발용으로 시작했지만 동시접속 한계, 터미널 끄면 죽고, 주소에 :8000이 붙어 실서비스엔 부적합.
  • 2
    Gunicorn 구니콘 (운영 앱서버)
    워커 3개로 동시 요청 처리, systemd 데몬으로 자동 재시작. Nginx와는 TCP가 아니라 유닉스 소켓(.sock) — 같은 서버라 더 빠르고 안전.
  • 3
    Nginx 엔진엑스 (웹서버)
    정적 파일은 Nginx가 직접 서빙해 부하↓. 80번 표준 포트에 띄워 URL에서 :8000 제거.
  • 4
    HTTPS 에이치티티피에스 전환
    80→443 리다이렉트, 사설망이라 자체 서명 인증서를 발급하되 SAN에 IP 명시. Nginx가 암호화 풀고 Django엔 평문 → SECURE_PROXY_SSL_HEADER·CSRF_TRUSTED_ORIGINS 짝맞춰 무한 리다이렉트·403 방지.
  • ·
    마무리
    브라우저→Nginx→유닉스 소켓→Gunicorn→DB, 완전한 프로덕션 파이프라인 완성.
  • ➡️
    전환 → 9번 (한빈님에게)
    "이 과정이 순탄치만은 않았습니다. 가장 큰 도전 두 가지는 한빈 팀원이 이어서 소개합니다."
📖 용어 (읽는법 · 뜻)
  • runserver런서버장고 기본 개발용 서버. 실서비스엔 부적합.
  • Gunicorn구니콘실서비스용 파이썬 앱 서버.
  • 워커Worker · 워커요청을 처리하는 일꾼 프로세스. 3개면 동시에 3개 처리.
  • systemd시스템디서버가 꺼져도 자동 재시작하게 관리하는 도구.
  • 유닉스 소켓 / .sock유닉스 소켓 · 닷 삭같은 서버 안 프로그램끼리 빠르고 안전하게 통신하는 통로.
  • TCP 포트티씨피 포트네트워크 통신용 번호. 소켓과 대비되는 방식.
  • HTTP / HTTPS에이치티티피 / 에이치티티피에스웹 통신 규약 / 그 암호화된 버전.
  • 리다이렉트Redirect · 리다이렉트다른 주소로 자동 이동(80→443).
  • 자체 서명 인증서Self-signed Certificate공인기관 없이 직접 만든 HTTPS 인증서. 내부망용.
  • SAN에스에이엔 (흔히 "샌")인증서에 유효한 도메인·IP를 명시하는 항목.
  • SECURE_PROXY_SSL_HEADER시큐어 프록시 에스에스엘 헤더"앞단 Nginx가 HTTPS로 받았다"를 장고가 믿게 하는 설정.
  • X-Forwarded-Proto엑스 포워디드 프로토Nginx가 장고에게 "원래 HTTPS였다"를 알려주는 값.
  • CSRF_TRUSTED_ORIGINS씨에스알에프 트러스티드 오리진스이 주소에서 오는 폼 요청은 믿겠다는 보안 설정. (CSRF=위조 요청 공격)
  • 403 에러사공삼권한 거부 오류.
